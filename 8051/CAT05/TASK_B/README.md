## TASK 5B: Software PWM Generation with Variable Duty Cycle

### 1. Circuit Diagram & Hardware Description

The experiment implements a software-based Pulse Width Modulation (PWM) system using Timer 0 of the AT89S52 microcontroller. The PWM signal is generated by repeatedly switching an LED ON and OFF with varying ON-time durations. The duty cycle is gradually increased from 0% to 100% and then decreased back to 0%, producing a visible LED fading effect.

- **Microcontroller:** AT89S52 (8051)
- **Timer Used:** Timer 0
- **Timer Mode:** Mode 1 (16-bit Timer Mode)
- **Clock Frequency:** 11.0592 MHz crystal oscillator.
- **Machine Cycle Duration:** Approximately 1.085 µs.
- **Timer Initial Value:** `0xFA9C`.
- **PWM Output:** LED connected to Port 1, Pin P1.1.
- **PWM Generation:** Software-based PWM using timer overflow polling.
- **Power Supply:** 5V DC regulated.
- **Development Environment:** Keil µVision using Embedded C (Keil C51).

### 2. Core Logic / Pseudocode / Code Base

#### Working Principle

The system generates a software PWM signal using Timer 0 overflow events. The duty cycle determines the proportion of time the LED remains ON during each PWM cycle.

The program uses four variables: `count`, `duty`, `fade_count`, and `increasing` to manage PWM generation and duty-cycle variation.

1. **Timer Configuration:** The TMOD register is configured with `0x01` to operate Timer 0 in Mode 1 (16-bit mode).
2. **Timer Initialization:** TH0 and TL0 are loaded with `0xFA` and `0x9C`, respectively.
3. **Timer Activation:** The TR0 bit is set to 1 to start Timer 0.
4. **Overflow Detection:** The program continuously monitors the TF0 flag to detect timer overflow.
5. **PWM Counter:** The variable `count` increments after every timer overflow and resets to zero when it reaches 100.
6. **PWM Generation:** The current counter value is compared with the duty-cycle value:
   - If `count < duty`, the LED is switched ON.
   - Otherwise, the LED is switched OFF.
7. **Duty-Cycle Control:** The variable `fade_count` tracks the number of timer overflow events. After 533 overflows, the duty cycle is updated.
8. **Increasing Duty Cycle:** When `increasing = 1`, the duty cycle increases in steps of 10%, starting from 0% and reaching 100%.
9. **Decreasing Duty Cycle:** When the duty cycle reaches 100%, the direction changes and the duty cycle decreases in steps of 10% until it reaches 0%.
10. **Continuous Fading:** The process repeats continuously, creating an LED fading effect.

#### PWM Duty Cycle and LED Brightness

#### Timing Calculation

**Given:**

- Crystal Frequency = 11.0592 MHz
- Timer Mode = 1 (16-bit)
- Timer Initial Value = `0xFA9C` = 64156

**Machine Cycle Duration:**

\[
T_{machine}=\frac{12}{11.0592\times10^6}
\]

\[
T_{machine}\approx1.085\ \mu s
\]

**Number of Timer Counts:**

\[
N=65536-64156=1380
\]

**Timer Overflow Duration:**

\[
T_{overflow}=1380\times1.085\ \mu s
\]

\[
T_{overflow}\approx1.497\ ms
\]

**PWM Period:**

The PWM counter cycles through 100 counts.

\[
T_{PWM}=100\times1.497\ ms
\]

\[
T_{PWM}\approx149.7\ ms
\]

**PWM Frequency:**

\[
f_{PWM}=\frac{1}{T_{PWM}}
\]

\[
f_{PWM}\approx6.68\ Hz
\]

**Duty-Cycle Update Interval:**

The duty cycle is updated after 533 timer overflows.

\[
T_{fade}=533\times1.497\ ms
\]

\[
T_{fade}\approx798.9\ ms
\]

Therefore, the duty cycle changes approximately every 0.8 seconds in steps of 10%.

#### Pseudocode

1. Include the 8051 register definition header file (`reg51.h`).
2. Define the LED output pin as P1.1.
3. Initialize the variables:
   - `count = 0` for PWM counter.
   - `duty = 0` for initial duty cycle.
   - `fade_count = 0` for tracking timer overflows.
   - `increasing = 1` for controlling the fading direction.
4. Configure Timer 0 in Mode 1 using the TMOD register.
5. Load TH0 and TL0 with the initial timer value `0xFA9C`.
6. Start Timer 0 by setting TR0 to 1.
7. Initialize the LED to the OFF state.
8. Enter an infinite loop:
   - Check whether the TF0 overflow flag is set.
   - If overflow occurs:
     - Clear TF0.
     - Reload TH0 and TL0.
     - Increment the PWM counter.
     - Reset the PWM counter when it reaches 100.
     - Compare the PWM counter with the current duty cycle.
     - Switch the LED ON if the counter is less than the duty cycle; otherwise, switch it OFF.
     - Increment the fading counter.
9. When the fading counter reaches 533:
   - Reset the fading counter.
   - If the duty cycle is increasing, increment it by 10.
   - If it reaches 100, reverse the direction.
   - If the duty cycle is decreasing, decrement it by 10.
   - If it reaches 0, reverse the direction again.
10. Repeat the process continuously to generate PWM with a gradually varying duty cycle.

#### Code Base

The program is developed using Embedded C in Keil µVision for the AT89S52 microcontroller. The `reg51.h` header file provides access to the 8051 hardware registers.

- The LED is connected to P1.1 and controlled using an `sbit` declaration.
- The TMOD register is configured with `0x01` to select Timer 0 in 16-bit Mode 1.
- The TH0 and TL0 registers are initialized with `0xFA` and `0x9C` to generate periodic timer overflow events.
- The TR0 bit is set to 1 to start Timer 0.
- The TF0 flag is continuously monitored to detect timer overflow.
- The timer registers are reloaded after every overflow to maintain a repeated timing interval.
- The variable `count` acts as the PWM counter and cycles from 0 to 99. It resets to zero after reaching 100.
- The variable `duty` stores the current duty-cycle value, initially set to 0.
- The PWM output is generated by comparing `count` with `duty`. When `count < duty`, the LED is switched ON by setting P1.1 LOW. Otherwise, the LED is switched OFF by setting P1.1 HIGH.
- The variable `fade_count` tracks the number of timer overflow events and determines when the duty cycle should be updated.
- When `fade_count` reaches 533, it resets to zero and triggers a duty-cycle update.
- The variable `increasing` determines the fading direction. When it is 1, the duty cycle increases by 10 until it reaches 100. When it is 0, the duty cycle decreases by 10 until it reaches 0.
- At the maximum and minimum duty-cycle limits, the fading direction is reversed.
- The entire process executes continuously inside an infinite loop, producing a gradual LED brightness variation.

### 3. Inference

**Execution Behavior:** Timer 0 is configured in 16-bit Mode 1 to generate periodic overflow events. These events are used to generate a software PWM signal whose duty cycle gradually increases from 0% to 100% and decreases back to 0%, producing an LED fading effect.

**Technical Learning Outcomes:** The experiment demonstrates timer configuration, overflow flag monitoring, software PWM generation, duty-cycle calculation, counter-based timing, and GPIO control using Embedded C on the AT89S52 microcontroller.

**PWM Understanding:** The experiment demonstrates how varying the duty cycle changes the average power delivered to an LED, thereby controlling its perceived brightness.

**Software Control:** The implementation demonstrates how timer overflow events and software counters can be combined to generate PWM waveforms and create continuously varying output patterns without using dedicated PWM hardware.
